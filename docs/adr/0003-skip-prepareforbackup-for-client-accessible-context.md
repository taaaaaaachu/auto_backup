# Don't call PrepareForBackup/BackupComplete under VSS_CTX_CLIENT_ACCESSIBLE

The snapshot-set creation sequence in `src/vss.rs` goes `SetContext` → `StartSnapshotSet` → `AddToSnapshotSet` → `DoSnapshotSet`, skipping `PrepareForBackup`/`AbortBackup`/`BackupComplete` entirely. This looks like it's missing steps compared to the general VSS requester sequence documented for `IVssBackupComponents`, but it isn't: per [Shadow Copy Creation Details](https://learn.microsoft.com/en-us/windows/win32/vss/shadow-copy-creation-details), `VSS_CTX_CLIENT_ACCESSIBLE` is one of the contexts that does **not** involve writers, and for those contexts calling `PrepareForBackup` (or `AddComponent`/`BackupComplete`) is documented to return an error rather than being merely unnecessary.

We hit this directly: an initial implementation that called `SetContext(VSS_CTX_CLIENT_ACCESSIBLE)` followed by `PrepareForBackup` failed on real hardware with `VSS_E_BAD_STATE` (`0x80042301`). Removing the `PrepareForBackup`/`AbortBackup` calls fixed it. If `PrepareForBackup` is ever reintroduced here (e.g. while adding writer-aware backup for app-consistent snapshots), the context must change to `VSS_CTX_BACKUP` or `VSS_CTX_APP_ROLLBACK` first, along with adding the `SetBackupState`/`GatherWriterMetadata`/`BackupComplete` calls those contexts require.
